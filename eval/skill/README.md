# Skill output checks

`check-rules.mjs` checks rule files written by the `learn-from-reviews`
skill against the `candidates` JSON the skill read. It needs no model and
no network, so it runs in CI (`npm run eval:skill`) over the gallery in
`examples/real-repos/*/plugin/`.

| Check | Fails when |
|---|---|
| `name` | the file isn't `pr-feedback-<kebab-case>.md` |
| `provenance` | the `<!-- Generated by reviewlore (learn-from-reviews) … -->` line is missing |
| `frontmatter` | frontmatter holds anything but `paths:` with quoted globs |
| `citations` / `citation-format` | fewer than 2 citations, or one isn't `— @author on PR #n: url` |
| `citation-source` | the URL isn't in the candidates file, or its author/PR differ |
| `verbatim` | the quote isn't in that comment's text (whitespace aside) |
| `evidence` | the citations cover fewer than 2 PRs or 2 reviewers |
| `scope` | a glob is invalid; the rule is scoped only to docs/tests/changesets although every cited comment was on source; or no glob matches a cited file and none covers source code |
| `anonymised` | an anonymised rule still contains an `@login` |

Comments the AI-reviewer filter drops never reach `candidates`, so a
quote from one fails `citation-source`.

```bash
node eval/skill/check-rules.mjs <rules-dir> <candidates.json>
npm run eval:skill
```

## Snapshots

`snapshots/<repo>.candidates.json` hold the clusters the gallery rules
cite, from `reviewlore candidates` run offline on the cached corpora.
Only cited clusters are kept, so they carry no reviewer handles beyond
those the gallery already shows. Rebuild them after changing the
extraction pipeline or regenerating the gallery:

```bash
node eval/skill/make-snapshots.mjs ~/.reviewlore
```

A rebuild that drops a cited quote is a pipeline regression for that
rule: fix the pipeline or regenerate the rule, don't edit the snapshot.
